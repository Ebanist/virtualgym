01 O projekcie

GymPlanner to aplikacja webowa (działa na telefonie i komputerze) dla bywalców siłowni. Wybierasz swoją siłownię, widzisz sprzęt dodany przez jej społeczność i układasz plany treningowe wyłącznie z ćwiczeń możliwych na tym sprzęcie. Potem prowadzisz trening krok po kroku z timerem przerwy i historią wyników.

Siłownie i sprzęt

  • Wyszukiwanie i dołączanie do siłowni
  • Sprzęt ze zdjęciami, historia zmian
  • Zgłoszenia usterek, oznaczanie „usunięty”

Ćwiczenia i plany

  • Biblioteka 67 ćwiczeń
  • Własne ćwiczenia: prywatne lub publiczne
  • Plany z dniami, kolejnością, kopiowaniem

Trening

  • Z dnia planu lub ad hoc
  • Serie, ciężar, poprzedni wynik
  • Timer przerwy, historia treningów

02 Technologie

Monorepo: backend/ (API), frontend/ (aplikacja w przeglądarce), docker-compose.yml (baza danych).

Backend

  • Java 21Wersja LTS, rekordy jako DTO.
  • Spring Boot 3.5Web, Data JPA, Validation – szkielet REST API.
  • Spring Security + JWTAccess token 15 min w pamięci, refresh token 30 dni w ciasteczku httpOnly z rotacją.
  • PostgreSQL 16Baza danych; rozszerzenie pg_trgm do wyszukiwania podobnych nazw.
  • FlywayWersjonowane migracje schematu – baza aktualizuje się sama przy starcie.
  • springdoc-openapi 2.9Opis API i Swagger UI; z niego generujemy typy dla frontendu.
  • Thumbnailator + TwelveMonkeysMiniatury zdjęć sprzętu (JPG/PNG/WebP).
  • Maven 3.9Budowanie – wrapper ./mvnw w repo, nie trzeba instalować.

Frontend

  • React 18 + TypeScriptInterfejs użytkownika z typowaniem.
  • Vite 8Serwer deweloperski i budowanie; proxy /api → backend.
  • React Router 6Nawigacja między ekranami.
  • TanStack Query 5Pobieranie danych z API, cache, odświeżanie.
  • React Hook Form + ZodFormularze i walidacja.
  • openapi-typescript + openapi-fetchTypy API generowane z backendu – jedno źródło prawdy.
  • react-i18nextWszystkie teksty po polsku w jednym pliku tłumaczeń.
  • CSS ModulesDesign „Volt Night”: motyw ciemny i jasny, fonty Space Grotesk + Inter.

Infrastruktura

  • Docker / Docker ComposeUruchamia PostgreSQL lokalnie jednym poleceniem.
  • Lokalny magazyn plikówZdjęcia w backend/uploads; interfejs gotowy pod S3/MinIO.

Testy i jakość

  • JUnit 5 + TestcontainersTesty backendu na prawdziwym PostgreSQL w kontenerze.
  • Vitest + Testing LibraryTesty komponentów frontendu.
  • oxlint + tscLint i sprawdzanie typów.
  • PlaywrightTesty przeklikania całej aplikacji (e2e) i zrzuty ekranu.

04 Instalacja na MacBooku (jednorazowo)

Wszystkie polecenia wpisujesz w aplikacji Terminal (Cmd + Spacja → „Terminal”).

  1. Narzędzia deweloperskie Apple

    Instaluje m.in. git. Potwierdź okno, które się pojawi.

    xcode-select --install

  2. Homebrew – menedżer pakietów

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
    Na końcu instalator pokazuje sekcję „Next steps” z dwoma poleceniami (echo … >> ~/.zprofile i eval …). Skopiuj je i wykonaj – inaczej polecenie brew nie będzie widoczne.

  3. Java 21, Node.js i Docker

    brew install --cask temurin@21
brew install node
brew install --cask docker

    Ustaw Javę 21 jako domyślną (raz):

    echo 'export JAVA_HOME=$(/usr/libexec/java_home -v 21)' >> ~/.zshrc
source ~/.zshrc
java -version   # powinno pokazać 21.x
node -v         # 20 lub nowszy

    Uruchom aplikację Docker z Launchpada i poczekaj, aż ikona wieloryba w pasku menu przestanie się animować.

  4. Pobranie kodu

    brew install gh
gh auth login                      # zaloguj się do GitHuba (przeglądarka)
gh repo clone Ebanist/virtualgym
cd virtualgym
git checkout claude/gymplanner-mvp-free-lbmx6x

05 Uruchomienie

Potrzebujesz dwóch okien Terminala (Cmd + T otwiera nową kartę) – backend i frontend działają jednocześnie.

  1. Baza danych

    W katalogu virtualgym (Docker musi być uruchomiony):

    docker compose up -d

  2. Backend – karta 1

    cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=dev

    Pierwsze uruchomienie pobiera zależności (kilka minut). Gotowe, gdy zobaczysz Started GymPlannerApplication. Profil dev wgrywa dane testowe do pustej bazy.

  3. Frontend – karta 2

    cd frontend
npm install
npm run dev

  4. Otwórz aplikację

    http://localhost:5173 – zaloguj się kontem testowym:

    E-mailHasłoSiłownie
    anna@example.comPassword123Fitness Arena Centrum (Warszawa)
    jan@example.comPassword123Fitness Arena Centrum, Iron Gym Kazimierz (Kraków)

Kolejne uruchomienia (na co dzień)

Instalacja jest jednorazowa. Później wystarczy: włączyć Dockera, a potem

cd virtualgym
docker compose up -d
cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev   # karta 1
cd frontend && npm run dev                                          # karta 2

Zatrzymanie: Ctrl + C w obu kartach, a bazę (opcjonalnie) docker compose stop. Dane w bazie zostają.

06 Przejście na nową wersję

Gdy dam znać, że jest nowa wersja (pojawi się też wpis w historii zmian):

  1. Zatrzymaj backend i frontend

    Ctrl + C w obu kartach Terminala.

  2. Pobierz zmiany

    cd virtualgym
git pull

  3. Uruchom ponownie

    docker compose up -d
cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=dev   # karta 1
cd frontend && npm install && npm run dev                           # karta 2

    npm install doinstaluje nowe biblioteki, jeśli się pojawiły. Zmiany w bazie (migracje Flyway) wykonują się automatycznie przy starcie backendu – Twoje dane zostają.

  4. Odśwież przeglądarkę

    Cmd + Shift + R (twarde odświeżenie).

Czysta baza od nowa (np. żeby wrócić do danych testowych). Usuwa wszystkie dane lokalne: 
docker compose down -v && docker compose up -d
Potem uruchom backend – seed wgra dane testowe ponownie.

07 Aplikacja na telefonie (ta sama sieć Wi‑Fi)

  1. Uruchom frontend dostępny w sieci

    cd frontend
npm run dev -- --host

    Vite wypisze dwa adresy. Na telefonie użyj adresu Network, np. http://192.168.1.23:5173 (nie localhost).

  2. Zezwól na połączenia przychodzące

    Ustawienia systemowe → Sieć → Zapora: zezwól dla node (albo tymczasowo wyłącz zaporę).

  3. Sprawdź sieć

    Telefon i Mac w tej samej sieci (nie „gość”), VPN wyłączony. Jeśli router izoluje klientów – użyj hotspotu z telefonu.
